# 元动作说明模板（primitive）

元动作对应一个关节或一个执行器的最小可控能力。它是最低层，仍然**不写驱动参数**，只描述"做什么、做到什么程度、怎么判断结果"。

写一份元动作说明时，按下面五节填，一节都不要省。

## 1 用途

一句话说清这个元动作改变什么物理量。

> 例：改变夹爪开合程度，不改变手臂位置。

不要写成"用于完成任务"这种没有信息量的话。

## 2 参数解释与单位

逐个列出用户需要给出的语义参数。每个参数写四项：

| 字段 | 说明 |
|---|---|
| 名称 | 用自然语言命名，例如"目标开合程度" |
| 含义 | 这个参数控制什么 |
| 单位 | 明确单位；无单位的写"无" |
| 是否必填 | 必填 / 可选（可选要写默认行为） |

规则：

- 只写**语义**参数。角度、速度、力矩、PID、坐标系这类驱动参数不写进这里。
- 单位的量纲要写死，例如"厘米"而不是"长度单位"。
- 如果数值范围来自下位机器能力，写"范围以当前能力快照为准"，不要自己编一个区间。

## 3 使用阶段

说明这个元动作一般在什么阶段被调用。

> 例：仅在已经接近目标、需要闭合夹爪时使用；不用于移动。

## 4 成功 / 失败 / 未知语义

三种结果都要写，不能只写成功。

- **成功**：可观测到什么现象才算成功。
- **失败**：什么情况下判失败，失败后这个元动作是否留下副作用。
- **未知**：什么情况下无法判断，此时不得宣称成功。

> 例：夹爪闭合到位只表示行程走完，不表示已经夹住物体。是否夹住属于未知，需后续动作确认。

## 5 例子

给 1–2 个自然语言例子，说明用户会怎么说、应该怎么理解。例子只写意图，不写参数 JSON。

> 例：用户说"夹紧一点" → 目标开合程度取更小值，具体数值以能力快照的可调范围为准。
